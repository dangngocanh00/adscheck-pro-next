# Fun Agency design guidelines

Direction: operational command center. Dense information uses dividers and hierarchy rather than decorative cards. Organization connectors, node borders, and region identifiers form the signature visual language.

- Be Vietnam Pro with 12/14/16/20/24/32 type scale.
- 4px spacing grid, 8px control radius, subtle elevation.
- Semantic CSS variables pair light and dark themes.
- Primary blue is reserved for actions and active state. Region colors only identify scope.
- Controls maintain visible focus and at least 44px hit areas for primary actions and interactive cells.
- Restricted fields preserve layout and show a lock with explanatory copy.
- Below 768px, tables become cards where appropriate and organization editing becomes a read-only breadcrumb browser.
- Motion is limited to 150–300ms state feedback and respects `prefers-reduced-motion`.
- The HR center uses one restrained signature element: a connected workflow ribbon from profile through payroll. Supporting screens remain data-dense and task-first.
- The operations inbox uses a dark SLA command strip as its single high-contrast signature. Work rows prioritize title, subject, owner, due time, and recovery path without card clutter.
- Electronic documents retain a neutral library surface; the detail view introduces a paper-like preview only where document context requires it.
- Approval screens use a master-detail command surface on desktop and a focused list/detail sequence on mobile. Decision context, handover, current level, and rejection reason stay visible before action.
- Employee self-service favors four direct request shortcuts, clear progress language, actionable rejection feedback, and safe cancellation before processing begins.
- The isolated Ads Save experience follows its reference brand: deep forest surfaces, mint workspaces, lime focus, and gold tutorial selection. Its Explore library keeps category navigation and the black tutorial viewport independently scrollable.
- Ads Check Pro reuses the same forest-and-mint product shell. After the extension-install gate, its asset workspace exposes VIA, TKQC, BM, Page, and Pixel tabs; folders, dense tables, function-library groups, and workflow controls share one responsive frame. Page/Pixel keep their source-observed wide schemas inside a local horizontal scroller and expose the collapsed workflow rail on desktop. Reference identities stay replaced with anonymous fixtures.
- Ads Check destination screens keep the same compact product chrome. Dashboard uses the observed two-step V8 story; Extended Payment, Billing, Notification, and the five-state asset workspace follow the captured hierarchy. Actions remain truthful local simulations and never imply a connection to source accounts.
- Extended Payment uses the captured 75/25 desktop split: white settings cards on the left and a tall forest-green Bubble preview on the right. The five general controls, 17 selectable fields, signature toolbar, promo card, and preview data remain operable; language, currency, exchange-rate, field, surface, and formatting choices visibly affect the preview. Below 1,000px the panels stack, and below 768px field controls use one or two columns with 44px toolbar targets.
- Billing uses the captured 70/30 desktop builder/summary split. The Pro/Priority hero pair, bundle row, Control Hub, feature catalogue, duration pills, coupon, balance switch, and disabled/enabled checkout states form one continuous purchase flow. The progress strip is semantic navigation rather than a false tab set; the three primary destination tabs retain roving keyboard focus, and checkout moves focus to its heading while preserving the builder state on return.
- Ads Check tables use semantic headers, labelled row selection, tabular figures, visible bulk-action scope, and card layouts below 768px. All mock identities, account IDs, session addresses, transaction values, and quotas are anonymous fixtures.
- Ads Check controls must produce truthful local feedback: partial table selection is visibly mixed, checkout preserves both the selected demo order and editable builder state, Priority cannot coexist with a partial Pro selection, coupon status clears when its value changes, Pro/regular session labels stay consistent across routes, and Extended Payment choices appear in preview before settings are saved locally.
